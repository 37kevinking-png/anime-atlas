# 番迹 · 我的动画生涯表

一个可以公开部署的静态网页，用年代、年份、季度和动画类型整理个人观看记录。

## 已实现

- 1917—1949年合并为“50年代前”，1950—1980年代按十年索引，1990—2030年按年份索引。
- 动画库可切换“日番 / 国产”：日番分为 TV、WEB、动画电影、剧场版和其他；国产暂按全部用户标签分为 TV、WEB、动画电影和其他，原始平台仍完整保留。国产时间轴把1990—1999合并为“90s”，2000年后逐年显示；明确晚于当前日期的预告条目会暂时隐藏，原始数据不删除。
- 国产资料包含 5,384 部带精确“中国”标签的动画条目；完整普通标签与蓝框公共标签保存在 `data/bangumi-cn/bangumi-cn.json`，浏览器包只带预计算类型、公共标签和首个普通标签，未来预告保留在原始缓存但不进入网页。
- 季度只作为TV动画的子分类，按1月番、4月番、7月番和10月番筛选。
- TV动画、WEB动画、动画电影、剧场版、其他五个一级分类；OVA、总集篇、光碟特典和设施限定短片统一进入“其他”。
- 资料库支持“海报＋信息 / 按月份表格”两种模式，切换时保持当前浏览位置。
- 资料库海报不再放置容易误触的加号；桌面右键、键盘菜单键或手机长按作品，可直接选择加入任意喜好主题。
- 生涯表海报墙与月份表格也支持右键/长按主题菜单；生涯海报会显示与资料库一致的蓝框公共标签。
- 支持按上映时间、bangumi评分、评分人数和名称排序，每种依据均可切换正序/倒序；默认按评分人数倒序。
- 评分人数少于10人的作品和总集篇作品分别默认折叠，可随时关闭折叠。
- 完整动画生涯表；每个单元格预留至少7部作品的显示空间。
- “刷刷刷”是默认首页，也保留在功能菜单：从符合筛选条件的已发布作品中随机生成四层斜向海报卡组；左滑看过、右滑没看过、上滑看过并推荐、下滑看过并不推荐。四种选择只写入生涯表及反应标记，不会自动加入喜好图鉴；卡片同步展示年份、评分和评分人数，点击左上角“番迹”也可随时回到首页。
- 刷刷刷支持按起始年份、最低评分人数（30 / 100 / 500 / 1000人或自定义）、最低/最高评分过滤，并可分别排除国产、WEB动画、动画电影、剧场版、总集篇及其他/OVA/短片；支持拖动、触屏手势、方向键和四个备用按钮，也支持连续撤回多步判断。
- 刷刷刷添加的作品会进入原有海报墙与完整表格；推荐作品标题以流动彩虹粗体显示，不推荐作品标题以黄色斜体显示。
- 右滑的“没看过”会单独保存在浏览器中，本轮及以后不再重复推送；可在刷番页面手动重置，也会随 JSON 备份一起导出和恢复。
- 浏览器本地自动保存。
- JSON备份导出、导入，以及资料缺失时的手动添加。
- 手机、平板和桌面布局；支持作为静态网站免费部署。
- 日番生成包会移除空字段与仅供审计使用的字段，国产浏览器包不重复携带完整普通标签层；当前两份前端资料合计约 9.6MiB，同时在原始 JSON/CSV 中保留完整标签与分类依据。
- 生涯表支持“海报墙 / 完整表格”两种展示方式；动画标题可直接打开对应番组计划详情，不再依赖悬停预览。
- 生涯表不再显示独立时间轴；逐年观看折线图的坐标点直接标注数量，点击点可筛选对应年份；可继续按类型及TV动画季度筛选，海报墙与完整表格同步响应。
- 个人动画总结：逐年观看折线图、密集年份、估算时长、热门/冷门作品和系列偏好。
- 系列偏好会展开每部相关作品的海报与名称。
- “安利关键词”读取“最想安利”清单；超过10部时以横向折线图展示前十个高频标签，并排除 TV、剧场版、动画电影等格式标签。
- “喜好图鉴”采用平铺的动画人格手账式 Bento 矩阵，集中展示 20 个默认主题，每个主题留一部代表作；默认主题不显示说明小字，自定义主题的说明可按需填写。
- 可从喜好图鉴直接生成高清PNG分享图：四页3:4图册、9:16竖版精选或完整长图；可隐藏空题和私人备注，并在支持的手机浏览器中直接调用系统分享。年度十佳使用“年度最佳 + 3×3补充”的专用海报图，十张海报最多三路并行预取并压缩到合适尺寸，避免瞬时请求过多导致海报回退。
- 分享图会自动尝试读取真实海报；番组计划图片端点不允许 Canvas 跨域读取时，经 wsrv.nl 只读图片缓存代理重试。正式部署到 HTTPS 域名后，分享图底部会自动附带进入网站的二维码，本地地址不会生成二维码。
- 首页直接进入刷刷刷；动画库、生涯表、喜好图鉴、年度十佳和刷刷刷作为五个独立入口，顶部默认只显示品牌与右上角三条线按钮，桌面与移动端点击后统一展开菜单，菜单项保持单行；刷番卡组居中，筛选面板默认收起，本地数据区会主动提醒导出备份。
- 每份清单可决定新增作品是否同步生涯表；“年度十佳”是独立页面，可自行选择年份，并进一步切换日番/国产、类型、日番电视季度、排序依据和正序/倒序。首部是无文字说明但有专属装饰的年度最佳，其余九部按 3×3 展示，选中区每张卡只显示海报和作品名称；鼠标和触屏均可拖动排序，导出使用同样的 1+3+3+3 结构。
- 年代坐标增加年份直达输入，减少长时间轴反复横向滚动。
- 生涯表会按评分人数找出最热门和最冷门作品；人数相同时再比较全部用户标签的标注总数。
- 评分至少30人时才显示番组计划分数；至少100人时才进入排行型统计。
- 海报评分采用缩小的右上角三角角标，分数沿三角斜边倾斜显示，桌面和移动端保持一致。
- 海报和月份表格会隐藏 TV、剧场版、OVA、动画电影等已由一级分类表达的格式标签；保留其余蓝框公共标签，并补充一个非蓝框普通标签。“日本 / 中国”等重复产地标签不展示。

## 直接打开

双击 `index.html` 即可使用。由于动画资料写入普通 JavaScript 文件，不启动服务器也能浏览和保存。

若要测试和实际部署环境一致的离线缓存功能，可在本目录启动任意静态文件服务器，例如：

```powershell
python -m http.server 4173
```

然后访问 `http://localhost:4173`。

## 更新动画资料

网页资料位于 `data/anime-data.js`。使用以下命令把“补番整理”流程生成的一个或多个 JSON 文件合并进网页：

```powershell
python tools/import_pipeline_data.py "data\classification\classified-movies.json" "data\classification\classified-tv.json"
```

当前日番资料包包含 12,704 部作品，来源包括：

```text
data\classification\classified-tv.json
data\classification\classified-movies.json
```

导入工具兼容当前 `enriched_movies.json` 字段，也接受网页统一格式。多个文件会按番组计划 ID 去重。

### 获取TV动画

推荐使用番组计划官方每周发布的 Wiki Data Public Archive。下面的工具不会下载完整归档，只会从远程ZIP中分段提取 `subject.jsonlines`，再筛选动画类型中的 TV 与 WEB 平台作品：

```powershell
python tools/fetch_bangumi_archive_tv.py --years 1917-2030
```

输出位于 `data/bangumi-tv/`：

- `bangumi-tv.json`：日期完整的TV动画与 WEB 动画；TV动画额外按月份分入四季度。
- `manual-review-missing-date.json`：缺少可用年份或日期、暂不应进入前台的条目。
- `summary.json`：年份、季度和数量统计。

如果官方归档暂时无法访问，也保留了逐年公开API抓取备用方案：

```powershell
python tools/fetch_bangumi_tv.py --years 1960-2030
```

两种方式都会落地缓存；中断后重复原命令即可。官方归档来源：[bangumi/Archive](https://github.com/bangumi/Archive)。

> 说明：`.cache/` 只用于本地数据处理，原始归档体积很大，不随网页部署；需要再次刷新资料时按上面的命令重新下载即可。Playwright 生成的 `tests/*.png` 也属于可重建的视觉回归产物，已在 `.gitignore` 中排除，避免推送到 GitHub 增大仓库体积。

### 获取早期日本动画

本地已有番组计划 `subject.jsonlines` 时，可从中提取1917—1959年作品：

```powershell
python tools/extract_bangumi_early_anime.py --subjects ".cache\bangumi-archive\dump-2026-08-25.210336Z.subject.jsonlines"
```

该步骤采用日本相关标签或条目正文中的国产来源描述做保守确认；无法确认国别的条目单独进入复核文件，不会混入正式资料库。

### 获取国产动画候选

本地已有番组计划 `subject.jsonlines` 时，可提取动画分类中带有精确“中国”用户标签的全部条目：

```powershell
python tools/extract_bangumi_chinese_anime.py --subjects ".cache\bangumi-archive\dump-2026-08-25.210336Z.subject.jsonlines"
```

输出包括 `data/bangumi-cn/bangumi-cn.json`、统计摘要和网页直接加载的 `data/anime-cn-data.js`。工具会同时保存每部作品的全部普通用户标签、蓝框公共标签、标注人数、原始平台、日期、评分人数与来源链接，后续调整国产分类时无需重新读取完整归档。

## 数据分类说明

- 分类读取番组计划条目下方全部用户标签：`总集篇`优先归入其他；只含`动画电影/电影`时归入动画电影；同时含`剧场版`和电影标签且关联既有 TV 系列时归入剧场版；同时含`剧场版`、`原创`和电影证据的独立作品归入动画电影。
- 番组计划平台为 WEB 的记录优先归入独立 WEB 动画分类；平台为 TV 或标签含`TV`的记录按首播月份归入四个季度。
- OVA、总集篇、光碟特典和设施限定短片统一进入“其他”，页面不继续展示细碎副分类。
- 标签缺失时，使用平台、标题和番组计划作品关联自动兜底。
- 页面展示归档`meta_tags`中的非格式蓝框公共标签，并补充首个有用的非蓝框普通标签；“日本 / 中国 / WEB”和重复格式标签会过滤。悬停人数优先显示归档中的真实标注数，归档未提供数字时明确提示“未提供人数”，不再伪装成0。
- 明确带有其他国家制作标签的作品在导入前排除；国家名只作为故事题材普通标签时不会误删日本作品。
- 分类不再以“是否院线上映”为主要标准。
- 自动分类审查表位于 `data/classification/classification-audit.csv`；当前没有需要人工确认的类型条目。
- 最新数据审查结果见 `DATA_AUDIT_STATUS.md`。

## 免费发布

这是纯静态项目，不需要传统服务器。可以将整个目录提交到 GitHub，然后使用 Cloudflare Pages、GitHub Pages 或 Vercel 发布。

Cloudflare Pages 的最简单设置：

1. 新建 Git 仓库并上传本目录。
2. 在 Cloudflare Pages 中连接该仓库。
3. 构建命令留空，输出目录填写 `/`。
4. 发布后使用平台提供的 `pages.dev` 地址访问。

## 隐私与数据来源

用户记录默认仅存于当前浏览器的 `localStorage`，不会上传。更换浏览器或清理浏览器数据前，请先使用“导出备份”。动画资料展示时保留番组计划和维基百科来源链接。

刷刷刷候选会自动排除生涯表里已经标记为“看过”的作品；这个判断读取所有页面同步到生涯表的记录，撤销记录后作品才会重新进入候选池。
